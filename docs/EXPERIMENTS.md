# Experiment Notes

This repository is a cleaned and reproducible reconstruction of a machine-learning course design completed in early 2024. The original work explored how CNN depth, filter counts, kernel sizes, pooling choices, and training duration affected image-classification performance on CIFAR-10 and MNIST.

## Historical results from the original report

The values below are transcribed from screenshots in the archived course report. They are **historical coursework results**, not benchmark claims and not newly regenerated by this repository. The old implementation repeatedly sampled subsets of the training data, so the historical numbers should not be treated as directly comparable to the reconstructed full-dataset workflow.

### CIFAR-10

| Experiment | Architecture change | Reported prediction accuracy |
|---|---|---:|
| Baseline | Conv filters 32 -> 64 -> 32, 3x3 kernels, three pooling layers | 58.6% |
| Smaller filters | 16 -> 32 -> 16 | 51.5% |
| Wider final layer | 32 -> 64 -> 64 | 55.7% |
| Two convolution layers | 16 -> 32, 2x2 kernels | 55.5% |
| Four convolution layers | 32 -> 64 -> 32 -> 64, 4x4 kernels | 60.3% |
| Four-layer model, longer training | Same four-layer model with more training | 64.3% |

The report concluded that the four-layer configuration benefited from additional training, while simply reducing or increasing filter counts did not guarantee better performance.

### MNIST

| Experiment | Architecture change | Reported prediction accuracy |
|---|---|---:|
| Baseline | Three convolution layers, three pooling operations | 98.1% |
| Four conv / two pool | Add one convolution layer and remove one pooling layer | 98.7% |
| Last pool changed to 1x1 | Preserve spatial resolution in the final pooling operation | 98.3% |
| Longer training | Same model trained for more iterations | 99.0% |

The report found that MNIST was substantially easier for these CNNs than CIFAR-10 and that a four-convolution/two-pooling configuration performed well in the tested setup.

## Reproducible presets

The reconstructed implementation turns the historical experiments into named model presets:

```bash
python src/train.py --list-presets
```

Examples:

```bash
python src/train.py --dataset cifar10 --preset baseline --epochs 20
python src/train.py --dataset cifar10 --preset four_layer --epochs 40
python src/train.py --dataset mnist --preset four_conv_two_pool --epochs 15
```

For a quick smoke run:

```bash
python src/train.py --dataset mnist --preset baseline --epochs 2 --train-limit 5000
```

`--train-limit` applies only to the training subset. Validation and test sets stay intact.

## Per-run artefacts

Each completed run writes under `results/<dataset>/<preset>/`:

- `metrics.json` - configuration, test/validation metrics, model size, timing and environment metadata
- `history.csv` - epoch-by-epoch training/validation history
- `per_class_metrics.csv` - per-class precision, recall, F1 and support
- `model_summary.txt` - Keras architecture summary
- `training_curves.png` - training/validation loss and accuracy curves
- `confusion_matrix.png` - test-set confusion matrix
- `prediction_examples.png` - intentionally selected correct and incorrect predictions with confidence
- `model.keras` - trained model, unless `--no-save-model` is used

Generated result directories are ignored by Git so trained models and experiment output do not accidentally bloat the public repository.

## Architecture comparison workflow

Run the documented experiment matrix:

```bash
python experiments/run_experiments.py --dataset all --epochs 20
```

The batch runner saves metrics and visualisations but skips the `.keras` model by default to reduce disk use. Add `--save-models` only when model files are actually needed.

At the end of the matrix, the runner automatically creates:

```text
results/experiment_summary.csv
results/experiment_summary.md
```

The summary ranks experiments within each dataset by test accuracy and reports test loss, best validation accuracy, parameter count, epoch count and training time.

Existing `metrics.json` files can be re-summarised without retraining:

```bash
python experiments/summarize_results.py
```

## Evaluation design

The reconstructed workflow adds several controls that were missing or fragile in the old scripts:

- consistent image normalisation for both training and test sets;
- deterministic random seed handling;
- deterministic class-stratified train/validation split;
- independent official CIFAR-10/MNIST test sets;
- full test-set predictions rather than manual evaluation of a partial slice;
- test accuracy/loss plus macro precision/recall/F1;
- per-class metrics and confusion matrix;
- explicit visual inspection of correct and incorrect predictions;
- run metadata for reproducibility and later comparison.

## What was improved from the coursework version

The portfolio version fixes syntax/indentation errors and several reproducibility problems in the original exported source files. It also:

- removes hard-coded Windows dataset paths;
- removes bundled virtual environments and IDE metadata;
- exposes experiment variants as named model presets;
- makes hyperparameters configurable from the command line;
- records parameter count, training time and software versions;
- automatically aggregates architecture comparisons;
- keeps historical coursework claims separate from newly reproduced results.
